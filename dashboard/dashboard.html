    A rolling 15-minute window of process list, sensors, fan, per-core CPU and the console's own time_uptime, diffed sample to sample. When the console stops answering or its uptime jumps backwards, the whole window is frozen to disk — the seconds before a crash are the part you cannot go back and ask for. Sampling is not nanosecond-resolution: each sample is an HTTP round trip, so the real period is tens of milliseconds. The nanosecond stamps order events exactly; they do not measure them.

    —
    The kernel maps two windows with an unmapped hole between them. sys_kern_rw is a bare memcpy with no fault handler, so a read into that hole would panic the console — the endpoint refuses any range that is not wholly inside one window.
    Kernel memory goes through sys_kern_rw, capped at 4 KB per request. Reading an unmapped kernel address faults the whole console — take addresses from the kernel base, do not guess them.

    Manual duty
    This bypasses automatic thermal control. Opcode 4 hands SYSCON a fixed duty and it stops following its own curve until the console is restarted or automatic mode is put back. Raising the duty cools harder and is the safe direction; lowering it is how hardware gets damaged. Nothing is written until you press Apply.
